01 / Online-kan website

  1. Ekstrak daps-network-portfolio-v2.zip. Ada dua folder: portfolio untuk GitHub Pages dan cloudflare-worker untuk backend admin.
  2. Masuk ke GitHub sebagai Rafa55603. Buat repo pribadi bernama daps-network dengan visibilitas Public agar dapat memakai Pages pada akun gratis.
  3. Di repo, pilih Add file → Upload files, lalu unggah isi folder portfolio. index.html harus ada langsung di root repo, bukan tersimpan satu folder lagi di dalamnya. Folder cloudflare-worker tidak perlu diunggah ke Pages.
  4. Pastikan file .nojekyll ikut diunggah. Jika tersembunyi, buat file itu melalui Add file → Create new file. Commit seluruh file ke branch main.
  5. Buka Settings → Pages → Deploy from a branch → main → / (root) → Save.
  6. Tunggu proses Pages di tab Actions berhasil. Gunakan alamat website yang muncul di Settings → Pages. Dengan nama repo di atas, alamatnya https://rafa55603.github.io/daps-network/.

Jika repo bernama lain atau memakai domain sendiri, gunakan URL dan nama repo yang sebenarnya pada seluruh langkah berikut. Dokumentasi Pages.

02 / Siapkan Cloudflare Worker dan database sesi

Gunakan dashboard Cloudflare. Nama menu dapat bergeser, tetapi layanan yang dipakai adalah Workers & Pages dan D1. Domain tambahan tidak diperlukan; alamat workers.dev bisa dipakai.

  1. Masuk atau buat akun Cloudflare.
  2. Buka Workers & Pages → Create application → Create Worker. Pilih starter Hello World bila diminta. Beri nama daps-admin, lalu Deploy.
  3. Catat URL Worker, misalnya https://daps-admin.SUBDOMAIN-KAMU.workers.dev. Gunakan alamat yang benar-benar diberikan Cloudflare.
  4. Buka Storage & databases → D1 → Create database. Beri nama daps-admin-sessions.
  5. Buka database itu, lalu tab Console. Salin seluruh isi file cloudflare-worker/schema.sql dari paket dan jalankan. Jika console meminta satu statement setiap kali, jalankan per statement yang diakhiri titik koma.
  6. Kembali ke Worker daps-admin. Di Bindings → Add binding → D1 database (pada beberapa tampilan ada di Settings), isi nama binding tepat DB, lalu pilih database tadi.
  7. Buka Edit code pada Worker. Ganti kode starter dengan seluruh isi cloudflare-worker/worker.js. File ini sudah mandiri dan tidak membutuhkan npm.
  8. Deploy. Login belum akan bekerja sampai pengaturan pada langkah 3–4 selesai; itu memang diharapkan.

D1 hanya menyimpan sesi login sementara dan token GitHub yang dienkripsi. Konten portofolio tetap berada di repo. Dokumentasi D1.

03 / Buat GitHub App khusus portofolio

Pilih GitHub Apps, bukan OAuth Apps atau Personal access tokens. Dengan GitHub App, akses dapat dibatasi ke repositori yang dipasanginya.

  1. Di GitHub, klik foto profil → Settings → Developer settings → GitHub Apps → New GitHub App.
  2. Nama aplikasi: misalnya Daps Network Admin Rafa55603. Jika nama sudah dipakai, tambahkan angka. Homepage URL: alamat website Pages milikmu.
  3. Callback URL: URL Worker diikuti /auth/callback. Contoh: https://daps-admin.SUBDOMAIN-KAMU.workers.dev/auth/callback. Jangan memakai alamat Pages pada kolom callback.
  4. Biarkan Request user authorization (OAuth) during installation tidak dicentang. Login dimulai dari website setelah instalasi selesai.
  5. Nonaktifkan Active pada Webhook. Layanan ini tidak memerlukan webhook, Setup URL, atau Device Flow.
  6. Pada Repository permissions, atur Contents → Read and write. Metadata Read-only mengikuti otomatis. Tidak perlu izin organisasi atau akun lain.
  7. Pada pilihan lokasi instalasi, pilih Only on this account. Klik Create GitHub App.
  8. Di pengaturan app, catat Client ID — bukan App ID. Pilih Generate a new client secret dan simpan rahasianya sementara di pengelola password.
  9. Masih di app, buka Install App → pilih akun Rafa55603 → Only select repositories → pilih daps-network → Install.

Client secret hanya dimasukkan ke Secrets Cloudflare pada langkah berikut. Jangan masukkan ke config.json, kode JavaScript, atau commit GitHub. Private key app tidak diperlukan untuk alur login ini.

04 / Sambungkan Worker, app, dan website

Di Worker → Settings → Variables and Secrets, tambahkan nilai berikut. Pilih jenis Secret untuk dua baris terakhir.

NamaJenisNilai
SITE_URLTextURL website penuh dengan / di akhir, misalnya https://rafa55603.github.io/daps-network/
GITHUB_REPOTextdaps-network, atau nama repo sebenarnya
GITHUB_BRANCHTextmain, atau branch sumber Pages
GITHUB_CLIENT_IDTextClient ID GitHub App tadi
GITHUB_CLIENT_SECRETSecretClient secret GitHub App tadi
TOKEN_SECRETSecretKunci acak untuk enkripsi sesi, minimal 32 karakter; buat 64 karakter dengan tombol berikut

Kunci ini dibuat di browser milikmu, tanpa dikirim atau disimpan oleh panduan:

  1. Simpan semua variabel dan secret, lalu Deploy Worker jika diminta. Pastikan binding D1 bernama DB tetap ada.
  2. Buka URL Worker diikuti /health. Setelah konfigurasi dan tabel benar, responsnya {"ready":true}.
  3. Di repo GitHub, edit config.json. Isi adminApiUrl dengan URL Worker tanpa / di akhir dan tanpa /auth/callback.
{
  "owner": "Rafa55603",
  "repo": "daps-network",
  "branch": "main",
  "contentPath": "data/content.json",
  "adminApiUrl": "https://daps-admin.SUBDOMAIN-KAMU.workers.dev"
}

Commit perubahan config.json dan tunggu Pages selesai. Akun yang berhak tidak ditentukan oleh config.json: Worker memverifikasi ID akun 72209248 pada server. Dokumentasi Secrets Cloudflare.

05 / Coba login dan publikasi pertama

  1. Buka website live → Admin → Masuk dengan GitHub.
  2. Di halaman resmi GitHub, pilih akun Rafa55603 dan izinkan GitHub App milikmu. Password GitHub hanya dimasukkan di GitHub, bukan di halaman portofolio.
  3. Setelah kembali ke website, dashboard akan terbuka jika identitas, instalasi app, dan akses repo benar. Akun lain ditolak server.
  4. Buka Profil & website, ubah satu kalimat, lalu Simpan ke editor → Terbitkan perubahan → Terbitkan sekarang.
  5. Pastikan commit baru muncul di repo. Tunggu proses Pages selesai lalu muat ulang beranda untuk melihat hasilnya.

Sesi editor ada di memori tab; refresh atau membuka tab baru mengharuskan login kembali. Sesi server berlaku maksimal satu jam dan editor mengakhiri sesi setelah 30 menit tidak aktif. Simpan form, lalu ekspor JSON bila perlu melanjutkan setelah login ulang.

Jika sebelumnya kamu membuat token manual untuk v1, kamu tidak perlu menempelkannya lagi. Gunakan tombol GitHub yang baru.

Mengelola proyek, artikel, dan profil

  • Proyek → Tambah proyek: isi judul, kategori, deskripsi, teknologi, dokumentasi, gambar, dan tautan. Pilihan unggulan menampilkan proyek di beranda; maksimal delapan proyek.
  • Artikel → Tulis artikel: isi tanggal, kategori, ringkasan, sampul, dan isi. Gunakan Pratinjau isi sebelum menyimpan.
  • Profil & website: ubah nama, bio, skill, email, foto, tautan sosial, dan teks beranda.
  • Simpan ke editor menyimpan sementara di tab. Terbitkan perubahan mengirim perubahan melalui Worker ke repo GitHub.
  • Ekspor JSON membuat cadangan. Overview → Pulihkan cadangan mengimpor file content.json ke editor. Impor mengganti isi editor; periksa sebelum menerbitkan.
  • Konflik sesi: bila file berubah di sesi lain, server menolak menimpa versi baru. Ekspor pekerjaanmu, login kembali, lalu gabungkan perubahan yang diperlukan.

Proyek dan artikel awal adalah contoh. Ganti dengan karya aslimu. Email dan tautan sosial belum diisi karena belum diberikan. Konten portofolio di repo publik dapat dibaca siapa pun; jangan gunakan artikel untuk menyimpan rahasia.

Gambar dan format tulisan

Unggah gambar ke folder assets melalui GitHub, lalu isi kolom gambar di admin dengan assets/foto-proyek.jpg. URL HTTPS gambar juga didukung. Foto profil menggunakan cara yang sama. Belum ada pengunggah gambar langsung di editor.
